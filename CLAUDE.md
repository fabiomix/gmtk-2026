# CLAUDE.md

Guidance for Claude Code in this repository.

## Project

**Project GLASSWING**: a top-down 2D escape roguelite in **Godot 4.7 / GDScript** (Compatibility renderer, 640x360 viewport). A captured spy escapes a secret lab against a countdown; captured runs restart from the cell, items can be kept only one at a time, knowledge (journal memories) persists.

`PROMPT.md` is the original prompt and game design (in Italian). It is a historical document, not kept in sync: where it differs from the code, the code and the section below win.

## Changes from PROMPT.md

- **Timer**: 60 s per run (prompt: 5 minutes).
- **Movement**: grid, Pokémon-style: 4 directions, 32 px tiles, 6 tiles/s; the player interacts with the tile it faces (prompt: free movement in 4 or 8 directions).
- **Rooms**: separate scenes linked by warp doors with a fade; the camera follows the player, black outside the room.
- **Map**: Cell — Corridor (hub) — Archive (north, optional), Storage (south), Laboratory (east) — Exit room. No Storage–Exit link.
- **Items** are never consumed.
- **Memories can open locks**: the archive cabinet opens with a combination learned from a note. Lock memories are recorded automatically when examining a lock, but are never required.

## Working with the user

- Write the files directly, then explain what was done and give a **manual test checklist**. Code, ids and comments in **English**; talk to the user in **Italian**.
- For design questions, propose a plan/analysis first and wait for decisions before writing code.
- The user play-tests every step **before** a commit. Ask before any git command and use exactly the commit message you showed.
- In-game text: concrete and in-world, no generic "slop". Propose drafts for approval. One message per interaction (don't stack notifications).
- Keep investigations proportionate: if the code answers the question, stop there. There is no GUI in this WSL environment (no screenshots); exports are done by the user from Godot on Windows.

## Commands

```bash
tools/run_tests.sh                                   # all headless tests (must end with ALL TESTS PASSED)
godot --headless --path . --script res://tests/test_journal.gd   # a single test
godot --headless --path . --quit-after 30            # smoke-run the main scene
godot --headless --path . --import                   # re-import after adding assets/classes
godot --headless --path . --script res://tools/gen_placeholder_art.gd   # regenerate placeholder PNGs
godot --headless --path . --script res://tools/gen_cover.gd             # regenerate itch/cover.png
godot --headless --path . --script res://tools/new_room.gd -- Name 10 7 5,6 crate:1,1   # new empty room
godot --headless --path . --script res://tools/resave_scenes.gd -- res://world/rooms/x.tscn  # add unique_ids after hand edits
```

## Architecture

- **Autoloads** (dependency goes one way: RunManager → GameManager, never the opposite):
  - `GameManager`: whole game (all runs): `keep_slots`, `kept_item_ids`, `discovered_memory_ids`, `new_game()`. Stores ids only.
  - `RunManager`: current run: countdown (`_physics_process`), `state` PLAYING/CAPTURED/ESCAPED (each end happens once), inventory, `start_run()`.
- **`main/main.gd`**: owns the loop. `_new_game()` → `_start_run()` (re-instantiates `world/world.tscn`: a fresh World resets all temporary state) → intro. Pauses the tree on capture/escape and wires Player signals to the HUD.
- **World** (`world/world.tscn`, must stay at (0,0)): rooms placed 1024 px apart, the Player, the fade layer. `world.gd` links doors by `door_id`/`target_door_id` and handles warps.
- **Rooms** (`world/rooms/*.tscn`): `Tiles` (TileMapLayer, 32 px, walls/crates on physics layer "world"), `Doors`, `Items`, optional `People`. Positions are tile centers: `(x*32+16, y*32+16)`.
- **Interactables**: any node in group `interactables`, on a tile center, with `get_prompt() -> String` ("" = nothing to do) and `interact(player) -> String` (message). The Player interacts with the tile it faces. Implementations: `Pickup`, `Cabinet` (required item and/or memory, contents, lock memory), `Door` (required item, lock memory), `Note` (adds a memory; no collision, put it on a wall/furniture tile).
- **Other world nodes**: `Exit` (Area2D in a wall gap, calls `RunManager.escape()`), `Scientist` (solid, decorative).
- **Data**: `data/items/<id>.tres` (`ItemData`), `data/memories/<id>.tres` (`MemoryData`: title, text with `{patrol}` placeholder, category NOTE/LOCK/INVESTIGATION). File name = id; logic compares ids, never display names.
- **UI** (`ui/`): HUD, PauseMenu, Journal, CaptureScreen, EscapeScreen, IntroScreen; CanvasLayers with process mode Always where they must work while paused.

## Conventions

- Files and folders `snake_case`, nodes and `class_name` `PascalCase`, scripts next to their scene.
- Placeholder art is generated by `tools/gen_placeholder_art.gd`; edit the generator, not the PNGs.
- Hand-written `.tscn` files: run `tools/resave_scenes.gd` on them afterwards so every node gets a `unique_id`, like the editor does.
- `itch/` holds itch.io material (cover); it has a `.gdignore`, so Godot neither imports nor exports it.
- Web export: preset "Web" in `export_presets.cfg` (no threads, excludes `tools/*` and `tests/*`), output in `build/web/` (git-ignored). Quit buttons are hidden on web.

## Testing pitfalls

- Tests extend `tests/test_base.gd` (loads Main, closes the intro, input helpers, `walk_to()`, `walk_into_door()`, route constants). Any engine error/warning during a test counts as a failure (custom `Logger`).
- A `--script` is compiled before autoloads exist: in tests use `root.get_node("RunManager")` and untyped/`Node` variables instead of autoload names or classes that use them (`HUD`, `Door`, `Pickup`...).
- Never `await` inside call arguments or `var x = await overridden_coroutine()`: it corrupts the coroutine state.
- Simulated input events (`Input.parse_input_event`) are delivered per process frame: wait with `await process_frame`, not physics frames.
- Long walking tests must stay under the run duration, or a capture will interrupt them.
